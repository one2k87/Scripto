# 애드센스 승인 여정 기록 — 5번 반려당하고 시스템으로 뚫은 과정

> **용도**: 지식상품/컨시어지의 원고 겸 증빙. 승인 확정일에 [결말] 칸만 채우면 출시 가능한 상태로 유지한다.
> **원칙**: 전부 실측 기록(DEVLOG·scripto_context 기반). 과장 금지 — "몇 회차에 승인되는가"로 경쟁하는 제품이므로 실패 기록 자체가 상품 가치다.
> 상태: **6회차 반려** (2026-09-04 접수 → 2026-09-11 '주의 필요·가치가 별로 없는 콘텐츠', D+7). 7회차 전략 = **주제 전환**(2026-09-11 사용자 확정): 셀프 인테리어(저경쟁 사냥·실수요 0) → 시니어 디지털 가이드(수요 있는 빈 니치). 기존 38편 비공개 보관, 페르소나 '이음' 도입, 검색의도 선행 분석 가동. 재신청은 새 주제 글 15편+ 색인 후.

## 1. 한 줄 요약

"글을 많이 쓰면 승인된다"는 통념으로 4번 반려당했다. 실측해 보니 문제는 글의 양이 아니라
**①글의 틀(클리셰) ②사이트의 구조(얇은 아카이브) ③구글이 사이트를 못 보고 있었다는 사실(색인 0)** 세 겹이었다.
세 겹을 각각 자동화된 점검·수리로 바꿨고, 그 자동화가 지금의 스크립토다.

## 2. 타임라인 — 반려 5회의 실측 원인과 조치

### 1~4회차 반려: "가치가 별로 없는 콘텐츠"
- **2026-08-22 라이브 사이트 전수 분석**으로 원인 확정 (추측이 아니라 실측):
  - 공개 글 ~45편 전부 외주 작성 글, 자동화 생산분 715편은 초안으로 잠겨 심사 대상에 없었음
  - 제목 어미 중복 50%("~방법"×3, "~알아보기"×2), 상투 표현 100%(총정리/알아야 할/제대로)
  - 도입부 100% 동일 틀("처음 접했을 때 저는 ~인 줄 알았습니다")
  - 글 1개짜리 태그 아카이브가 글 수만큼 색인 → 얇은 중복 페이지 양산
  - 태그라인 공백, 메뉴와 글 주제 불일치
- **자기모순 발견(핵심 교훈)**: 생성 프롬프트가 품질 게이트가 걸러낼 글("총정리 제목", "직접 해보니" 겪지 않은 경험담)을 **지시**하고 있었다. 반려 원인의 절반은 도구 자신에게 있었다.
- 조치: 외주 중단, 프롬프트 전면 교체(경험 조작 금지), 태그 전량 삭제·noindex, 제목 골격 분산기, 도입부 클리셰 검사를 **매일 자동 점검**으로 상시화.

### 5회차 반려: 숨은 원인 = 구글에게 빈 사이트였다
- **2026-08-31 Inspection API 30개 전수 검사**: 홈만 PASS, **글 29편 전부 "URL is unknown to Google"**.
  글을 아무리 고쳐도 구글 인덱스에는 사실상 빈 사이트 — 4번의 수정이 심사관에게 보이지도 않았다.
- 조치("색인의 재발명"): ①매일 Inspection API로 재크롤 넛지+색인 신호등(index_status.json) ②IndexNow·WebSub 자동 통지 ③**색인 신호등이 기준을 넘기 전에는 재신청 자체를 막는 게이트** — "날짜가 됐으니 재신청"을 금지.

### 6회차: 시스템이 갖춰진 뒤의 신청
- 함정 실측: 재신청 쿨다운은 **태평양 시간 기준**이고 해제도 즉시가 아님(배치 지연) — 예약 신청 2회 불발 후 확인.
- 신청 전 상태: 색인 사전점검 29/30 PASS, 발행 글 평균 96점, ads.txt 매칭, 필수 페이지·소개(팀 명의) 완비.
- **2026-09-04 08:03 접수 → 2026-09-11 반려**("가치가 별로 없는 콘텐츠", 6회 연속 동일 사유).
- 6회차의 교훈(반려 후 전수 실측): 색인·품질점수·구조는 다 갖췄는데도 떨어졌다 — 즉 남은 원인은 **글 자체의 성격**이다. ①제목이 키워드 뭉치("1mm 오차 없이…공식 프로토콜")로 기계 냄새 ②니치가 '셀프 인테리어'가 아니라 '저경쟁 마이크로 상황 사냥' 목록으로 보임 ③정책·지원금 글 혼입(니치 밖) ④28일 검색 클릭 1 = 실수요 검증 0 ⑤100% AI 생산·경험 부재. 저경쟁 키워드 최적화가 만든 구조적 맹점.
- 심사 중 사이트 정화: 죽은 초안 1,053편 휴지통, 통계를 살아있는 36편 기준으로 재구성, GSC의 404/noindex 알림은 정화의 정상 잔재로 판독(수정하면 죽인 글이 부활).

## 3. 이 여정에서 나온 제품 기능 (= 상품 목차 초안)

| 겪은 문제 | 만들어진 기능 |
|---|---|
| 반려 사유가 추상적("가치 없음") | 사이트 자동 점검(제목 골격·도입부·중복·소개 충실도) + 한 번에 고치기 |
| 프롬프트가 게이트와 모순 | 생성↔검수 일관성 원칙(프롬프트 수정 시 게이트 교차 확인) |
| 색인 0을 아무도 몰랐다 | 색인 신호등 + 재크롤 넛지 + 신청 게이트 |
| 재신청 타이밍 함정(PT 기준) | 신청 절차 가이드·예약 설계 |
| 심사 중 실수 유입 위험 | 심사 모드(초안 잠금) + 라인 격리(제휴 혼입 원천 차단) |
| 승인 후 급변 리스크 | 승인 램프(3~4주 점진 전환: 발행 2→5편/일·광고 0→3개, 원탭 시작) |
| 매일 봐야 하는 부담 | 아침 자동 점검+텔레그램, 검수 자동화(오늘도 정확성 미달 글 2편 자동 폐기) |

## 4. 증빙 수집 (자동 + 수동 2장)

**자동** — `증빙 캡처` 워크플로(evidence-capture.yml)가 찍어 `docs/증빙/<날짜>/`에 커밋한다.
승인 원탭 절차가 승인 당일 자동 발동하고, 심사 중 수동 실행분은 '이전 상태' 기준선이 된다:
원더랜드 홈 · ads.txt · 앱 홈(모드 카드·D+n) · 앱 승인 탭(여정 스테퍼) · 앱 글 탭

**수동 2장만** (구글 로그인 화면이라 자동화 대상 외 — 승인 후 1시간 안에):
- 애드센스 승인 메일/화면(사이트 상태 "준비됨")
- GSC 색인 그래프(정화 후 우상향)

DEVLOG 해당 구간은 git 이력이 원본 타임스탬프 증빙.
